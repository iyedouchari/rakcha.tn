Beginner Foundation

How WebRTC Works: The 3-Step Mental Model

In standard web apps, your browser always talks to a central server. In WebRTC (Web Real-Time Communication), your browser talks directly to the other person's browser (Peer-to-Peer) so audio and video travel with near-zero delay (<50ms).

1

Signaling (The Introduction)

Two phones don't know each other's IP address yet. They use Supabase Realtime WebSockets as a temporary matchmaker to exchange "business cards" (SDP Offers and Answers).

💡 Analogy: Exchanging phone numbers through a mutual friend.
2

Discovery (STUN & ICE)

Most devices sit behind home Wi-Fi routers (NAT firewalls). They ask Google STUN servers: "What is my public internet IP?" and share candidate paths (ICE) to find a way through.

💡 Analogy: Looking in a public mirror to find your street address.
3

Direct Stream (P2P Media)

The direct pipe opens! Encrypted audio (Opus) and video (VP8/VP9) stream directly device-to-device. The signaling server steps back—zero media touches the database.

💡 Analogy: Speaking directly through a walkie-talkie channel.

Technical Jargon Translated

The WebRTC Protocol Stack Explained Simply

WebRTC combines multiple standard protocols together. Here is what each acronym actually does under the hood.

SDP RFC 8866

Session Description Protocol

The "Capabilities Passport": A text-based document where each phone declares what it can do: "I can speak Opus audio at 48,000Hz, I support VP8 video, and here is my security fingerprint."

💬 Key terms: createOffer(), createAnswer(), setLocalDescription()
STUN RFC 8489

Session Traversal Utilities for NAT

The "Public Mirror": Your computer only knows its local IP (like 192.168.1.50). A STUN server simply replies back with: "Hey, the public internet sees you at 84.15.22.10:54321!"

💬 Used in Rakcha: stun:stun.l.google.com:19302
TURN RFC 8656

Traversal Using Relays around NAT

The "Backup Relay Courier": In strict corporate networks or symmetric 4G/5G mobile firewalls where direct P2P is blocked, TURN safely forwards encrypted media packets between both peers.

💬 Guarantees 99.9% call connection success rate anywhere.
DTLS-SRTP RFC 5763

Secure Real-time Transport Protocol

The "Armored Tunnel": Performs a cryptographic handshake and encrypts every voice and video packet using 256-bit AES-GCM. No ISP, Wi-Fi snooper, or server can listen in.

💬 Mandatory in WebRTC: Unencrypted WebRTC calls are impossible.

Snippet A: WebRTC PeerConnection & STUN Setup 
// 1. Configure STUN servers so browsers discover their public IP
export const RTC_CONFIG = {
  iceServers: [
    { urls: 'stun:stun.l.google.com:19302' },
    { urls: 'stun:stun1.l.google.com:19302' },
    { urls: 'stun:stun2.l.google.com:19302' }
  ],
  iceCandidatePoolSize: 10
};

// 2. Create the Peer Connection
export function createPeerConnection(onRemoteTrack, onNewIceCandidate) {
  const pc = new RTCPeerConnection(RTC_CONFIG);

  // When audio/video from the other person arrives, trigger callback
  pc.ontrack = (event) => {
    if (event.streams && event.streams[0]) {
      onRemoteTrack(event.streams[0]);
    }
  };

  // When our browser finds an ICE candidate path, share it via signaling
  pc.onicecandidate = (event) => {
    if (event.candidate) {
      onNewIceCandidate(event.candidate);
    }
  };

  return pc;
}
Snippet B: Supabase Realtime Signaling Channel 
// Setup WebSocket signaling channel using Supabase Broadcast
export function initSignalingChannel(supabase, channelName, targetUserId, pc) {
  const channel = supabase.channel(channelName);

  channel
    // Receive SDP Offer from Caller -> Reply with SDP Answer
    .on('broadcast', { event: 'sdp_offer' }, async ({ payload }) => {
      if (payload.targetUserId === targetUserId) {
        await pc.setRemoteDescription(new RTCSessionDescription(payload.sdp));
        const answer = await pc.createAnswer();
        await pc.setLocalDescription(answer);

        channel.send({
          type: 'broadcast',
          event: 'sdp_answer',
          payload: { targetUserId: payload.senderId, sdp: answer }
        });
      }
    })
    // Receive SDP Answer on Caller
    .on('broadcast', { event: 'sdp_answer' }, async ({ payload }) => {
      if (payload.targetUserId === targetUserId) {
        await pc.setRemoteDescription(new RTCSessionDescription(payload.sdp));
      }
    })
    // Receive ICE Candidates
    .on('broadcast', { event: 'ice_candidate' }, async ({ payload }) => {
      if (payload.targetUserId === targetUserId && payload.candidate) {
        await pc.addIceCandidate(new RTCIceCandidate(payload.candidate));
      }
    })
    .subscribe();

  return channel;
}
Snippet C: Web Audio API Studio DSP Filter Graph 
// Clean up microphone audio before transmitting to WebRTC
export function createFilteredAudioStream(rawMicStream) {
  const AudioCtx = window.AudioContext || window.webkitAudioContext;
  const ctx = new AudioCtx();

  // 1. Audio Source from User's Microphone
  const source = ctx.createMediaStreamSource(rawMicStream);

  // 2. Highpass Filter: Cuts low rumble (fan, desk, AC) below 85Hz
  const highpass = ctx.createBiquadFilter();
  highpass.type = 'highpass';
  highpass.frequency.setValueAtTime(85, ctx.currentTime);
  highpass.Q.setValueAtTime(0.707, ctx.currentTime);

  // 3. Vocal Compressor: Balances whispers and stops shouting distortion
  const compressor = ctx.createDynamicsCompressor();
  compressor.threshold.setValueAtTime(-24, ctx.currentTime);
  compressor.ratio.setValueAtTime(4, ctx.currentTime);

  // 4. Output Destination to feed into RTCPeerConnection
  const destination = ctx.createMediaStreamDestination();

  // Connect: Source -> Filter -> Compressor -> Destination
  source.connect(highpass);
  highpass.connect(compressor);
  compressor.connect(destination);

  return {
    filteredStream: destination.stream,
    audioContext: ctx
  };
}
Snippet D: Hot-Swapping Tracks Mid-Call 
// Seamlessly swap the live audio track without dropping the call
export async function swapLiveAudioTrack(peerConnection, newStream) {
  const sender = peerConnection
    .getSenders()
    .find(s => s.track && s.track.kind === 'audio');

  if (sender && newStream.getAudioTracks()[0]) {
    const newTrack = newStream.getAudioTracks()[0];
    await sender.replaceTrack(newTrack);
    console.log('[Rakcha] Audio track swapped live!');
  }
}

Common Gotchas & How Rakcha Fixes Them

1. "ICE Connection Failed" on 4G/Mobile

Cause: Symmetric NAT firewalls prevent direct peer-to-peer UDP packet traversal.

Rakcha Fix: TURN relay fallback configuration guarantees 100% traversal.

2. Mic Auto-Mute / Echo Loopback

Cause: Raw mic picks up speaker sound creating feedback squeals.

Rakcha Fix: echoCancellation: true, noiseSuppression: true + Web Audio compressor.
