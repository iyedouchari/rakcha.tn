=========================================
RAKCHA.TN - PROJECT ANALYSIS & FEEDBACK
=========================================

1. WHAT IS CURRENTLY THERE (Current State)
------------------------------------------
- Frontend Stack: React 19, Vite, Tailwind CSS, Zustand (for state management), and Radix UI (for accessible components).
- UI/Pages Structure:
  - Landing Page
  - Authentication (Login / Register)
  - Profile Creation
  - Dashboard (Main App interface)
  - Create/Join Group flows
  - Settings & Discover pages
- State Management (Zustand):
  - A central store (`useRakchaStore.js`) is managing the application state.
  - Currently uses MOCK DATA (hardcoded `MOCK_USER`, `MOCK_GROUPS`, and mock messages).
  - Handles UI state for joining calls (toggling mic/camera/screen share).
  - Handles navigation using a custom Hash-based routing system (`#/landing`, `#/app`).

2. WHAT IS MISSING TO CONFIRM THE IDEA'S FUNCTIONALITY
------------------------------------------------------
To turn this from a "UI Prototype" into a fully functioning application, the following is missing:
- Backend Server: Although `express` and `cors` are listed in your `package.json`, there is no actual backend code (no server.js or API routes). You need a dedicated Node.js server.
- Database: There is no data persistence. You need a database (like MongoDB, PostgreSQL, or Firebase) to store Users, Groups, and Messages. Right now, a page refresh will reset all data.
- Real Authentication: The login/register pages are just UI. You need a real authentication system (JWT, NextAuth, or Firebase Auth) to securely sign users in.
- Real-Time Communication: You have `socket.io-client` installed, but the messages in the store are just pushing to a local array. You need to connect this to a real Socket.io backend to broadcast messages to other users.
- Voice/Video Calls (WebRTC): The store has `joinCall`, `toggleMute`, and `toggleCamera`, but this only changes UI icons. You need WebRTC (like SimplePeer or mediasoup) to actually transmit audio and video between users.
- File Uploads: Uploading profile pictures, group icons, and message attachments requires a storage solution (AWS S3, Cloudinary, etc.).

3. FEEDBACK AND THINGS MISSED (Best Practices & Architecture)
-------------------------------------------------------------
- Mixed Dependencies: Your `package.json` contains both frontend (`vite`, `react`) and backend (`express`, `cors`) dependencies. It is highly recommended to separate them. Create a `frontend` folder and a `backend` folder, or use a framework like Next.js if you want them together.
- Routing System: Using `window.location.hash` for routing works, but it's very basic and can cause issues as the app grows. It is highly recommended to switch to `react-router-dom` for better URL management, route protection (e.g., blocking the dashboard if not logged in), and a smoother user experience.
- Folder Cleanup: There is a folder named `stitch_nexus_communication_hub (2)` which seems disconnected from the main React app. If these are old prototypes or unused assets, consider cleaning them up to keep the workspace tidy.
- Security: Right now, invite codes and group IDs are generated on the client side (`Math.random()`). In a real app, this MUST be generated on the secure backend to prevent users from manipulating data or hijacking groups.

Overall, the UI foundation and the component structure look fantastic! You have a very solid base to start wiring up a real backend.
